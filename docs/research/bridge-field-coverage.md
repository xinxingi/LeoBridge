## 本次数据准备实现（覆盖下文早先的“未接入”状态）

按用户要求，本次只补数据准备与可靠衍生，不扩大主题兼容范围。新增 `src/core/prepared-data.ts`，由中立模型统一调用；CFSM节点及Komari节点、最新状态、近期报告通过 `bridge.data` 输出同一份白名单数据。

| 数据组 | 已准备的数据与计算 | 口径 |
| --- | --- | --- |
| resources | 内存/磁盘剩余及占比、总网速、TCP+UDP、每逻辑CPU负载 | bytes、B/s、百分比；剩余不是Linux MemAvailable；缺项不当0 |
| billing | 原币价格/币种、CNY价、续费周期月数、月/年成本、源展示到期日与倒计时 | 按日历月折算，不把一个月转成30天；倒计时按UTC日历日期，源到期日不冒充合同时间戳 |
| traffic | 源、scope、方向、调整量、用量、限额、余额、超额、占比、周期日期 | 保留Xray与system区别；有reported用量时不重复加调整量；仅已知源/范围/模式及显式调整量时从U/D推导用量 |
| traffic.boot / cumulative | 两套源累计字段及current_boot范围、上下行合计 | 不映射成跨重启/月流量，不混合两组不同来源计数器 |
| traffic.daily | 日期、上下行、总量与已返回日期汇总 | 缺日不补0；缺方向不补0；重复/非法日期使账本不可用；不声称完整月账本 |
| ping | 全部唯一key目标的当前值/桶、桶级min/max/mean与有效桶数 | 不受CFSM八槽限制；保留缺值，不生成逐包统计/分位数；重复key不映射 |
| sourceMetadata / returnRoutes / unlocks | 核心数候选、地区/城市、服务商与安全HTTP(S)链接、回程、解锁 | 白名单输出；不把cpu_cores候选冒充已核实物理核心 |
| 历史 bridge.sourceCounters | cumulative_up/down源桶值 | 中立历史保留11项；两个协议保留源累计桶，不差分成精确流量，resetScope仍未知 |

## 实现前的结论与验证方式

当前CFSM/Komari适配集中在CPU、内存、磁盘容量、实时网速、在线状态、运行时间、系统信息、连接数及部分系统/Ping历史。价格、到期、周期流量、开机累计、服务商、回程与解锁，源端已有但双生态尚未接入。**原生协议单独实现公开字段转发，已经保留这些数据；不能笼统称整个桥接器都没适配。**

对20:44保存的真实11台快照及单台历史，使用现有身份绑定运行当前CFSM服务、Komari RPC和原生服务，778项字段等值/单位/连接合计检查通过。原生输出未丢弃该快照的任何服务器字段，系统历史11项与源逐项相同；CFSM/Komari系统历史保留其中9项，未接入`cumulative_up/down`。这是实际源码对真实响应的回放检查，不是新造数据，也不是用户运行实例或主题兼容验收。证据：`work/bridge-coverage/check.ts`、`summary.json`。

实际查看用户提供的原生页面：首页指标、资源历史弹窗、周期日流量弹窗、解锁详情。原域名在内置浏览器首次访问及重载均只显示背景；之后通过临时回环只读代理取得原站HTML/JS和同源真实公开数据，页面成功渲染。已核对该域与保存的数据源相同；既有Token只在本机服务端给三个明确的公开探针接口添加，不给页面或第三方资源。未转发WS，不能据此声称原站直接访问或WS已验收。

页面脚本为`probe-page-BncDFCNC.js`，本轮完整文件SHA-256：`bf57702cb12d0b08a890c9c373eaaeb0d69ee70f1fea4ab0a296c9ddc5cb00b9`；它是运行主控的构建材料，不是固定原生独立前台仓库的版本声明。实际摘要见`work/bridge-coverage/page-evidence.json`，原始文件只存忽略目录。下面把页面可见数据作为存在证据，并单独核对聚合方式，不再用“当前双生态输出为空”推断源端缺失。

## 明确的桥接缺口与边界

1. CFSM `service.ts`的`show_price/show_expire/show_tf`固定为false，且节点价格/到期未输出、流量字段为null。补字段时还须补显示能力开关，单独把源字段读进来不足以展示。
2. Komari `komariNode`将price/billing_cycle/expired_at/traffic_limit写成null；`komariStatus`固定`ping:{}`。已有历史Ping不等于所有实时摘要已适配。
3. 中立模型没有价格、周期/开机流量、服务商、回程、解锁、完整地区等。因此两个输出协议都无法消费它们；原生路径直接投影公开源字段，已有这些能力。
4. 原生不是任意字段透传。本次服务器字段全保留，但顶层`block_login/show_name/show_forward`未原样输出：名称隐私由服务端执行，原主控登录不接入；`show_forward`是否需要在未来消费者版本中补充应单独核对。本轮不能因此称“所有未来源字段都已支持”。
5. 源未返回的Swap/GPU/IO/进程/虚拟化/稳定ID等仍保持未知。本轮查看的页面中也没有看到这些项目；这不证明私有后端不存在这些能力。

建议后续先完成价格/到期/续费周期、开机累计、周期流量与日趋势，再补Komari当前Ping摘要及目标数量限制；回程和解锁先确认目标主题扩展契约。它们是适配工作，不应继续列为妙妙屋基础数据全缺失。
