## 先核实协议

实际连接7897成功，随后独立核查：

- HTTP `CONNECT` 到已配置主控目标返回200。
- SOCKS5握手选择无认证方法，目标CONNECT响应代码为0（成功）。

因此该端口实测同时支持HTTP CONNECT与SOCKS5，不能仅凭端口惯例推断协议。本轮HTTP及WS对照选择已核实的 `http://127.0.0.1:7897`；SOCKS5只确认协商/CONNECT，没有额外发出重复历史请求。

## 同一历史接口限量对照

两次请求均读取已授权主控：`/api/public/probe-series?server=0&metric=system&range=1h`，携带同一有效探针Token。仅改变直连/代理路径；没有自动重试。curl采用HTTP/1.1、连接截止15秒、总体截止45秒；直连明确禁用代理，代理路径明确指向本机7897，不修改全局设置。

| 方式 | curl退出码 | HTTP状态 | TCP连接完成 | TLS完成 | 首字节 | 总时间 | 完整响应 |
| --- | ---: | --- | ---: | ---: | ---: | ---: | --- |
| 直连 | 28 | 000（未收到HTTP） | 0 | 0 | 0 | 15.006秒 | 否，0字节 |
| HTTP CONNECT代理 | 0 | 200 | 0.000250秒 | 0.801791秒 | 0.960793秒 | 0.963946秒 | 是，4906字节 |

代理CONNECT状态为200；业务响应`success=true`、`bucket_sec=300`，11个系统字段各12点。直连的三个阶段完成时间均为0，只能确定截止前未完成TCP/未收到HTTP，**不能将此样本误写成已确认的TLS失败或鉴权失败**。代理样本的TCP时间衡量到本机代理的连接，不能与直连到源站的TCP耗时作同口径延迟比较。

这是一组限量诊断样本，支持优先使用用户授权的本机代理继续当前开发联调；不是长期性能基准，不能证明所有直连故障均由同一原因引起，也不能证明增加HTTP超时已解决网络问题。

## 原生WebSocket代理采样

同一已核实HTTP代理进行45秒只读WS采样：CONNECT200、HTTP101，TLS完成0.752秒、首字节0.893秒。收到565565字节，解析得到**9个完整原生快照帧，其中5个不同完整内容**。到45秒上限后工具关闭连接，curl退出28；这表示有界采样结束，不能把已成功握手和连续帧记作失败。帧可重复当前源端状态，内容不同不要求每一帧都成立。

本工具只保存流字节后解析，不记录每帧到达时刻，因此不能由9帧/45秒进一步宣称每个相邻间隔严格5秒或长期稳定性已通过。与此前直连长时间收不齐帧相比，本轮代理连续读取完整快照已得到证据。

## 原始材料与复现

`scripts/diagnose-proxy.py`只从本地`.dev.vars`读取主控配置，将URL和密钥通过stdin传给curl，不在命令参数或stdout输出这些值；响应、响应头、curl错误与摘要写入被忽略的`work/private/proxy/`。目录权限0700、文件0600。stdout只有协议状态、HTTP状态、时间及结构计数，不含真实服务器名称或指标值。

```sh
python3 scripts/diagnose-proxy.py protocols
python3 scripts/diagnose-proxy.py direct
python3 scripts/diagnose-proxy.py http
python3 scripts/diagnose-proxy.py ws-http
```

代理请求要求先保存对应端口的成功协议证据。脚本默认不自动重试、不跟随重定向、不读取curl个人配置，不改变全局代理。WS采样到期会关闭连接，curl28在HTTP101情形下需要与已收到的完整帧分别解读。

本机代理地址只对运行这台机器的本地Node进程有意义，**不能直接配置给Cloudflare Workers云端**。Node的undici/WS实际代理接入、本地桥接器重启及浏览器验收由各自实现和验收记录确认；curl对照本身不能替代这些检查。Workers云端链路仍需目标环境独立验收。
