# 主题管理

## 首次启动与已有安装

默认只交付桥接器和自有管理界面，不内置第三方主题。新实例先从 `/admin/` 登录（默认密码须先改密），再在[数据源设置](configuration.md#后台配置数据源)连接妙妙屋X。数据源就绪后，选择CFSM或Komari商店，查看来源与许可信息、确认安装、预览后再启用。isolated模式使用配置的独立管理源。

升级不会删除已有主题，不改变active/previous指针，也不自动安装或启用新的默认主题。历史主题及许可档案见[来源记录](references/retired-themes/README.md)。备份时继续保存完整状态目录；只保存项目构建产物不能恢复已安装主题。

## 安装、预览与切换

1. 从侧栏选择「CFSM 商店」或「Komari 商店」，点击主题的「查看并准备安装」。阅读来源、固定版本与许可信息，主动勾选后确认安装；详见[安装确认流程](#主题获取与许可信息)。
2. 在「已安装主题」中打开「预览」，检查首页、节点详情、历史图表及实时状态。预览使用当前数据源，不会替换正在展示的主题。
3. 对未验证的版本，核对预览后按页面提示确认并启用。刷新展示首页以加载新主题。
4. 需要恢复时，在工作台回退到上一版本；其他已安装版本也可再次预览和启用。安装新版本不会自动替换当前主题。

默认single模式只需一个域名和一个端口：例如 `https://monitor.example.com/?__preview=<安装ID>`。预览页面、资源、HTTP接口和实时连接按请求绑定安装版本，不使用全站预览Cookie，不改变active指针，可同时打开多个版本。详情跳转及刷新保留预览参数；直接打开不带参数的首页查看正式主题。Caddy/nginx配置见[单域名反代](deployment/reverse-proxy.md)。

同域名预览不提供主题与管理后台的安全隔离，只预览和启用可信主题。需要独立源隔离时显式选择isolated模式，并配置独立管理、展示和预览域名。此模式保留原来的版本及预览子域路由。

## 双商店与主题存储

管理站分别读取官方CFSM、Komari商店，将`main`解析为具体提交后展示目录；通常缓存60秒，刷新按钮重新解析。安装请求携带用户看到的`catalogRevision`，不会在点击时静默改用更新目录。CFSM分支进一步固定到commit；Komari包校验目录中的ZIP SHA-256。保留来源、版本、许可证及安装记录。

两套商店卡片显示主题GitHub仓库的Star数，默认从多到少排列，同数保持目录顺序。服务端读取GitHub公开仓库页面中的精确计数，不用页面上的k缩写估算，也不消耗目录及安装使用的REST API额度。Node进程缓存成功结果1小时，失败5分钟；刷新目录保留有效Star缓存，并重试缺失或过期项。更新失败时最多保留24小时内成功取得的旧数值，悬停标明获取时间与缓存状态。仓库404、没有受支持地址或始终读取失败的以“-”显示并排最后，真实0单独显示。Star读取沿用商店下载网络设置，最多并发6项、单项10秒、每批30秒截止，重复仓库与并发请求合并；页面返回429时遵守限流暂停。Star数只表示仓库关注数，不代表主题兼容性。

“可发现”“已安装”“已验证兼容”是不同状态。商店包默认未验证，需先预览并明确确认才能启用；缺失入口或资源、摘要不符、危险路径、符号链接和不支持文件类型会拒绝。许可文件缺失或文本不属于已识别的标准许可证，不再单独阻止安装，但必须展示信息并由用户确认。当前静态包限额：压缩包16,000,000字节、展开总量32,000,000字节、单文件8,000,000字节、最多1200条目、最大压缩比200。只安装允许的静态文件，不运行包内脚本构建或服务端程序。

每个安装ID固定资源与protocolProfile；single模式用预览参数选择，isolated模式用独立版本及预览主机选择。默认single模式切换或回退会关闭展示根入口的旧实时连接，需要刷新首页；预览页面与独立版本主机继续绑定各自版本。安装完整写入后才公布元数据，安装失败不改变当前启用版本。启用/回退要求最新generation，旧管理页面会收到冲突并需刷新。

Node通过原子文件替换和跨进程锁保存状态。Workers通过R2保存每个安装的一份拼接静态包，按资源偏移进行range读取；单站Durable Object以事务保存安装元数据、active/previous指针及管理会话。没有D1，也不把指标或历史存进DO/R2。当前没有主题卸载或孤立包自动清理界面；部署后需按实际存储量安排维护。

single预览在响应HTML最前注入请求及历史导航适配，不修改已安装包的原始文件、摘要或许可证。fetch、XHR及WebSocket等请求附带版本参数；根路径资源、CSS依赖和模块导入通过同源Referer补齐参数并重定向到版本化地址。代理需保留查询参数和Referer，不能强制去掉同源Referer或缓存这些重定向；主题自行禁止Referer、移除参数或覆盖适配的特殊行为仍需逐包检查，不承诺所有主题通用。

第三方主题CSP限制同源资源和网络连接，阻断外链、iframe及Worker/Service Worker。可静态识别的外部依赖会在安装时拒绝，运行时动态引用仍需浏览器验收。尚无主题配置编辑UI：Komari `raw`/`redirect`配置拒绝，`managed`配置保持当前默认行为。不能保证所有第三方主题都支持这些限制或LeoBridge协议子集。


## 主题获取与许可信息

1. 点击“查看并准备安装”，服务端从固定目录下载包并执行安全检查，尚不写入安装资源或改变活动主题。
2. 查看实际固定版本、上游来源、许可原文与文件列表。没有可用的明确许可文件时提示“未发现明确许可文件”；未知文本保留原文，标识NOASSERTION，不按许可证类型判断是否可用。文本识别仅供参考；非UTF-8文本显示替换字符，包内原文件字节保留。
3. 主动勾选以下文案，再点击“确认安装”；不预勾选。取消不会安装，准备记录15分钟后失效，同一会话重新准备会替换旧记录。

> 我已查看上游来源及可用的许可说明，了解 LeoBridge 不提供授权判断，并决定安装此主题。

安装时重新下载所查看的固定版本，验证完整包摘要与准备时一致；CFSM固定到当时的Git提交，不重新解析移动分支。记录保存在管理会话存储中，支持服务重启；换会话、退出、改密、过期或内容变化均不能沿用原确认。最终提交再验证确认记录，写入失败不改变活动主题。

安装元数据保存来源、固定版本、包摘要、许可信息状态、确认时间和提示文案版本/原文。重复确认同一安装只更新确认记录，不切换活动主题。旧安装没有记录时如实显示“历史安装，无本流程的确认记录”，不补造授权或确认。

确认只记录知情安装决定，不是授权证明；来源文件存在、用户确认、包安全检查及实际兼容性各自独立，不显示“许可通过”。保留许可原文、字体与图形声明；不把项目MIT套用到主题。

商店原版仍需实际浏览器验证首页、详情、历史、实时及异常状态。历史适配包的验收结论不能转移给未修改的原版。优先在桥接协议内解决兼容问题，无法正确表达数据的主题明确记录限制。

## 管理面板外观

右上角的太阳、月亮和显示器图标分别选择白天、夜间和跟随系统模式，登录页也可切换。首次访问默认夜间；选择保存在当前浏览器，同一管理站的其他标签页会同步更新。

「跟随系统」会随系统深浅色设置自动变化；手动选择白天或夜间后不受系统变化影响。浏览器禁止本地存储时仍可在当前页面切换，但无法记住选择。该设置只影响管理面板，不改变已启用的展示主题。

安装流程与真实商店原包检查见[验收记录](research/theme-store-transition.md)。Emerald七天图表登录限制及两套原版的未知值显示问题仍存在，不承诺全部主题兼容。

## 商店下载网络

商店代理默认关闭。后台“商店下载设置”可开启HTTP/HTTPS代理并填写地址，保存后用于两套商店的目录、许可文件及主题包下载。代理连接由LeoBridge服务器发起，Docker中不要把容器自身的127.0.0.1误当宿主机；代理失败不会自动直连。设置、认证信息保留和部署地址说明见[商店下载代理](configuration.md#商店下载代理)。
