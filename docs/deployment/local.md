# 本地部署（预编译运行包）

普通用户下载对应系统、架构的运行包，解压后直接启停。包内带有Node、应用、生产依赖和管理资源，目标机器无需安装Node、npm或pnpm，也不需要编译。

**发布状态：目前尚未在GitHub Releases公开发布运行包。** 以下约定用于运行包交付和使用；发布后请选版本附件中的`leobridge-<版本>-<系统>-<架构>.tar.gz`，不要下载GitHub自动生成的`Source code`源码归档作为运行包。自行构建见[开发文档](../development/build.md)。

## 获取和启动

1. 选择与目标机器系统、架构匹配的运行包，同时下载该包的`.sha256`文件。Linux官方Node运行时需要glibc；Alpine等环境建议使用Docker镜像。
2. 校验下载摘要，例如Linux用`sha256sum -c <包名>.tar.gz.sha256`，macOS用`shasum -a 256 -c <包名>.tar.gz.sha256`，确认通过后解压。
3. 进入解压后的目录执行：

```sh
./leobridge.sh start
```

启动只使用包内已有程序，不联网下载运行环境、不安装依赖或构建。缺少文件或运行时不匹配会报错，此时应重新下载完整的匹配包。无参数运行`./leobridge.sh`等同于start；若执行权限未保留，可用`bash leobridge.sh start`。

程序默认后台运行，关闭终端后继续运行，只监听本机`127.0.0.1:8787`。首次启动不需要上游凭据或第三方主题。需要Bash；当前打包目标为Linux/macOS x64/arm64，实际可用平台以已发布附件及验收记录为准。

## 初始化

1. 打开[管理后台](http://127.0.0.1:8787/admin/)，首次使用`admin` / `admin`登录，设置新密码后重新登录。
2. 在“数据源设置”填写妙妙屋X主控地址与Token，检查连接，核对节点身份和最多8个Ping目标后保存。
3. 在CFSM或Komari商店查看来源和许可信息，主动确认安装，预览后启用。
4. 打开[展示首页](http://127.0.0.1:8787/)，检查节点、详情、历史及实时更新。

本地预览使用`*.localhost`，需浏览器支持回环解析。默认同源展示与管理，只应启用可信主题；需要独立源时按[配置参考](../configuration.md)使用isolated模式。运行包可直接启动，但连接数据源和浏览主题商店仍需相应网络。

## 后台管理

| 命令 | 行为 |
| --- | --- |
| `./leobridge.sh start` | 后台启动；已运行时不重复创建进程 |
| `./leobridge.sh stop` | 停止本脚本启动的服务；已停止时可重复执行 |
| `./leobridge.sh restart` | 等待旧进程退出，再使用当前配置启动 |
| `./leobridge.sh status` | 查看运行状态、PID、启动时间、管理入口和日志路径 |
| `./leobridge.sh logs` | 输出最近最多100行运行日志（最多读取64KiB） |
| `./leobridge.sh help` | 查看命令帮助 |

静默启动使用`./leobridge.sh start --quiet`；正常输出隐藏，失败仍报告错误。运行日志在`work/local/service.log`，持续查看可用`tail -f work/local/service.log`。启动时日志超过5MiB会保留为`service.log.1`；运行期间不自动轮转，长期运行需管理日志容量。

成功退出码为0，操作失败为1，参数错误为2，status确认未运行时为3。启动成功表示应用全部端口就绪，状态正常不等于上游或主题兼容验收通过。停止先发送SIGTERM，等待最多10秒后终止仍未退出的应用进程。

脚本通过仅监听回环的控制端口和私有令牌管理当前目录实例，不按旧PID记录直接杀进程；状态无法确认时会报错。后台管理进程退出时应用也会退出。系统重启后需重新start，崩溃不会自动拉起；需要开机自启和自动恢复时交给系统服务管理器或使用Docker重启策略。

## 配置与持久化

默认`work/theme-store`保存全部主题、active/previous、管理密码摘要、会话及数据源凭据。可用`BRIDGE_THEME_STORE`指定独立持久目录。`work/local`仅保存日志和进程控制记录；不要在运行中删除它，也不要把它复制为新实例的控制记录。

脚本始终以解压目录为工作目录。默认local模式读取该目录的私有`.dev.vars`；proxy/direct模式使用显式`BRIDGE_ENV_FILE`。环境变量优先于文件。端口默认8787，例如在`.dev.vars`写`PORT=8788`后restart生效；已有显式origin或监听配置优先。临时命令`PORT=8788 ./leobridge.sh start`不保存该变量，下次restart需要再次提供，因此长期参数建议保存在私有文件中。

配置文件、状态备份和日志应限制访问，不原样贴到工单。已有后台配置、管理密码和稳定节点ID均随业务状态保留，不随重启重新生成。

## 备份、升级和回退

1. 下载并核对新版本运行包，解压到新目录，保留旧版本。
2. 在旧目录执行stop，备份完整`work/theme-store`及私有配置。只备份state.json或程序文件不够，主题资源也必须保留。
3. 将完整业务状态和配置迁移到新目录，或让新包的`BRIDGE_THEME_STORE`指向原独立数据目录的绝对路径。不要复制旧work/local进程记录，不要同时启动两个写入者。
4. 从新目录start，验证管理登录、数据源、主题资源及历史/实时功能，确认正常后再清理旧包。

升级替换整个运行包，包括内置运行时和依赖；不要仅替换一个JS文件。跨版本状态降级尚无保证，应用回退时停止新实例，恢复对应版本完整备份和旧程序。管理界面的主题回退不能替代应用回退。

## 对外访问

应用只负责HTTP监听和持久化，不管理域名、DNS或证书。需要对外访问时，由部署者配置nginx或Caddy提供反向代理、HTTPS及证书续期；DNS在域名服务商处配置。

按[Node运行参数](../configuration.md#node运行参数)设置proxy模式、访问源和可信代理地址。连接、身份及图表问题见[排障指南](../troubleshooting.md)。
