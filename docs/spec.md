# v0.1 开发规格

状态：2026-11-02，固定CFSM默认前台本地验收已完成；双生态主题管理与真实Komari主题也已完成本地验收，VPS私有实例现已运行且接口/运维检查通过，浏览器及公网验收仍待完成。新的用户决定优先于本文。

## 结果

在不增加服务器Agent、不运行CFSM或Komari完整后端的前提下，用两个生态的实际前台展示妙妙屋X已有探针数据。提供独立双商店主题管理、本地开发及VPS部署包。当前按用户最新要求优先VPS/Node，Cloudflare Workers部署后置。2026-11-03用户已提供测试VPS并选择仅SSH隧道私有测试；本轮可完成该测试环境部署，不开放公网展示。

## 范围

- TypeScript 数据访问、数据模型和协议适配。
- `/api/config`、`/api/servers`、`/api/server`、`/api/history/all`、`/api/ws`，以实际前台依赖为准。
- 主题首页、服务器详情、已有指标历史、实时刷新及必要静态资源。
- Token 服务端保存；明确访问策略、超时、缓存和重连行为。
- 可复现构建、部署配置、最小环境变量示例和故障排查说明。

当前阶段新增双商店轻量管理后台、动态安装/预览/启用/回退和一个真实Komari前台的公开协议兼容；不以架构预留作为完成。全部第三方主题兼容、CFSM Agent、告警和新历史数据库不在范围。主题中不支持的源端管理能力必须有明确行为，不得假装成功。

- 整理现有职责目录和README，保留上游来源/许可证/历史证据，增加自动依赖边界与循环检查。
- 提供Node可信TLS反代运行方式、Docker Compose/nginx及持久化/备份/升级说明；默认不加载开发秘密文件。

- Workers现有代码与证据保留，不作为当前默认部署路径。

## 前期实施顺序

1. 阅读固定材料，完成默认前台调用与静态资源依赖审计；解决或明确身份映射约束。
2. 建立 TypeScript 工程、统一模型、上游客户端、合成样例和关键转换测试。
3. 实现配置、列表、详情和主题静态页面，浏览器验证。

5. 补齐错误处理、部署配置、CI 和用户文档；使用授权的真实主控联调。

## 完成标准

- 干净检出可以按 README 完成安装、配置、构建和本地启动。
- 类型检查、构建及关键测试通过，结果有记录。
- 默认前台首页、详情、历史、实时更新在浏览器实际验证。
- 名称隐藏、空列表、离线、零值、缺省、身份歧义、排序变化、上游失败和断线恢复具有测试或明确的验收证据。
- 明确支持的历史范围；不插值冒充真实采样、不伪造七天数据。
- 主题资源路径完整、用户可看到合理的降级及错误信息。
- 交付兼容清单、配置示例、部署步骤、来源及许可证说明。
- 模拟验证、真实主控验证、Workers 实际部署验证分别记录。缺凭据可交付待联调版本，但不能标记整体验收完成。

## 当前产品验收：双生态主题管理

- LeoBridge 独立轻量后台提供 CFSM 与 Komari 两个商店入口；服务器管理仍由妙妙屋X负责。
- 发现、可安装、已验证兼容分别记录；来源索引与包格式按生态适配，不假定稳定 API。
- 主题记录包含 ecosystem、来源、上游版本、许可证、兼容状态及资源入口。
- 单展示站一次启用一个主题；安装、版本固定、预览、启用和回退共用管理能力。切换无需改代码或重新部署，并原子绑定正确输出协议与资源版本，处理旧连接。
- 后台与第三方主题及预览按独立源隔离，后台独立认证；Token 只保留服务端。
- Workers 动态资产及元数据方案、成本与后续验收见 [ADR 001](decisions/001-theme-protocol-boundaries.md)。兼容结论仅覆盖实际验收的Adhesive Note适配包，不代表全部Komari主题。
- 必须完成本地双商店实际安装、版本固定、隔离预览、启用/回退、失败原子性与并发冲突验证；选定许可明确的Komari真实主题，验收首页、详情、历史、实时，并回归CFSM。
- 实时优先原生上游WS，保留退避、清理及过期提示；初始化和历史按需要使用HTTP。使用已授权本机7897代理验证，不因本地workerd网络超时停止独立功能开发。
